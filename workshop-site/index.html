Hands-on lab · OpenTelemetry Java Contrib · Splunk Observability Cloud

IBM MQ metrics with OpenTelemetry Java Contrib

Clone this repo, run IBM MQ locally, export queue metrics with OpenTelemetry Java Contrib ibm-mq-metrics, and view ibm.mq.* metrics in Splunk Observability Cloud.

Everything you need is in this repo

Docker Compose stack (MQ, Java exporter sidecar, OTel collector, sample apps), config files, and this guided site. No second repo required.

Step 1~5 min

Prerequisites

  • Docker Desktop (or Docker Engine + Compose v2)
  • Git
  • Splunk Observability Cloud ingest token (facilitator-provided or your org’s token)
  • Node.js 20+ (optional — for npm run load-traffic only)

Apple Silicon: services use linux/amd64; first build of ibm-mq-java-metrics (Gradle) can take 10–15 minutes.

Step 2~2 min

Clone the repo

Terminal
git clone https://github.com/garrett-splunk/MQ-Java-Otel-Workshop.git
cd MQ-Java-Otel-Workshop
Step 3~5 min

Splunk Observability Cloud token

Terminal
cp .env.splunk.example .env.splunk
vi .env.splunk

Replace your-ingest-token-here with your ingest token. Match SPLUNK_REALM and URLs to your org (us1, eu0, etc.). Never commit .env.splunk.

Verify (no token printed)
test -f .env.splunk && echo "OK: .env.splunk present"
grep -q 'your-ingest-token-here' .env.splunk && echo "WARN: replace placeholder token" || echo "OK: token line edited"
Step 4~2 min

Lab environment

Terminal
cp .env.example .env

Default demo MQ password is passw0rd (MQ_APP_PASSWORD in .env). The Java exporter uses the same credentials via Compose environment variables.

Step 5~10–20 min first build

Start the stack

Builds and starts: IBM MQ, OpenTelemetry Collector, ibm-mq-java-metrics sidecar, order producer/consumer, and the local workshop site.

Terminal
docker compose up --build -d

Watch the Java exporter (Gradle build on first run):

Terminal
docker compose logs -f ibm-mq-java-metrics

What gets deployed

ibm-mq-java-metrics/ clones opentelemetry-java-contrib v1.59.0, builds the shadow JAR, and scrapes MQ via PCF every 15s. Config template: ibm-mq-java-metrics/config.lab.yml.

Step 6~5 min

Verify the stack

Terminal
bash scripts/verify-stack.sh

Checks producer/consumer health, collector, workshop site, Java metrics container, and a sample order.

Local workshop UI: http://localhost:8091 · MQ console: http://localhost:9443/ibmmq/console (admin / password from .env)

Step 7~5 min

Generate traffic

Terminal
curl -X POST http://localhost:8080/orders \
  -H "Content-Type: application/json" \
  -H "X-Correlation-Id: demo-1" \
  -d '{"productId":"SKU-JAVA","quantity":2}'

npm run load-traffic -- 30 400

Queue depth on ORDER.REQ should change — visible in ibm.mq.queue.depth after the next scrape.

Step 8~10 min

Find metrics in Splunk Observability Cloud

  1. Open Metrics → Metric Explorer.
  2. Filter: deployment.environment:ibm-mq-lab
  3. Search metric names containing ibm.mq (not ibmmq).
  4. Chart ibm.mq.queue.depth; filter dimension queue = ORDER.REQ if available.

Upstream reference

ibm-mq-metrics README — full metric list and production configuration options.

Troubleshooting

SymptomThings to check
ibm-mq-java-metrics build fails Network for Git/Gradle during docker compose build. Allow extra time on Apple Silicon (amd64 emulation).
MQ auth errors in Java logs Channel MQOTEL.SVRCONN in mq/20-lab-connect.mqsc; password matches MQ_APP_PASSWORD in .env.
No ibm.mq in Splunk .env.splunk token; collector on :13133; wait 1–2 scrape intervals (15s) plus batch (5s).
verify-stack.sh fails on Java container docker compose logs ibm-mq-java-metrics — container may still be building on first start.

Teardown

Terminal
docker compose down -v
