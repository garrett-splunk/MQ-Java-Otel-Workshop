Hands-on lab · OpenTelemetry Java Contrib · Splunk Observability Cloud

IBM MQ metrics with OpenTelemetry Java Contrib

Export IBM MQ queue and queue-manager metrics using the community OpenTelemetry Java Contrib ibm-mq-metrics PCF monitor. Metrics arrive in Splunk Observability Cloud with the ibm.mq.* naming convention.

Lab stack

This workshop uses the same Docker Compose stack as the main IBM MQ lab (MQ-O11y-Workshop). Complete the main lab Steps 1–6 first, then return here for the Java exporter track.

Step 1~5 min

Prerequisites

Complete Steps 1–6 of the main workshop first:

  • Clone MQ-O11y-Workshop and add your Splunk Observability Cloud token to .env.splunk
  • docker compose up --build -d with healthy MQ and collector
  • bash scripts/verify-stack.sh passing

The same OTel collector forwards both exporters to Splunk Observability Cloud — no collector changes required.

Step 2~2 min · optional

Disable the embedded mq_otel exporter (recommended)

By default the MQ container runs IBM’s Go exporter alongside QM1. For a clean comparison, stop it so only Java Contrib metrics appear under ibm.mq.

Terminal
cd ~/projects/ibm-mq-o11y-lab
DISABLE_MQ_OTEL=true docker compose up -d --force-recreate mq

Confirm mq_otel is not running:

Terminal
docker compose logs mq 2>&1 | tail -20
# Should NOT show "Starting mq_otel metrics exporter"

Skip this step if you want both exporters running (you will see both ibmmq.* and ibm.mq.* in Metric Explorer).

Step 3~10–15 min first build

Build and start the Java Contrib exporter

In the MQ-O11y-Workshop repo, the service lives in ibm-mq-java-metrics/. The Dockerfile clones opentelemetry-java-contrib at tag v1.59.0, builds the shadow JAR, and runs PCF collection in client mode every 15 seconds.

Terminal
cd ~/projects/ibm-mq-o11y-lab
docker compose --profile java-contrib build ibm-mq-java-metrics
docker compose --profile java-contrib up -d ibm-mq-java-metrics

Watch startup (Gradle build happens on first build; allow several minutes on Apple Silicon under amd64 emulation):

Terminal
docker compose --profile java-contrib logs -f ibm-mq-java-metrics

Configuration is rendered from ibm-mq-java-metrics/config.lab.yml at runtime (MQ host, channel, OTLP endpoint). Queue filters include ORDER.* and DEV.QUEUE.*.

Step 4~5 min

Verify metrics reach the collector

Terminal
curl -s http://localhost:13133/metrics | grep -E 'otelcol_receiver_accepted_metric_points|ibm\.mq' | head -20

Generate traffic so queue depth moves (same as main lab Step 8):

Terminal
curl -X POST http://localhost:8080/orders \
  -H "Content-Type: application/json" \
  -d '{"productId":"SKU-JAVA","quantity":1}'

npm run load-traffic -- 20 300
Step 5~10 min

Find metrics in Splunk Observability Cloud

  1. Open Metrics → Metric Explorer.
  2. Filter: deployment.environment:ibm-mq-lab
  3. Search metric names containing ibm.mq (not ibmmq).
  4. Chart ibm.mq.queue.depth and filter dimension queue = ORDER.REQ if available.
  5. Optional: compare with main-track names (ibmmq.queue.depth) if you skipped Step 2.

Resource attributes

Java Contrib sets queue manager and object dimensions on each metric (for example queue, queue_manager). Exact dimension names may differ slightly from mq_otel — use Metric Explorer’s dimension picker after selecting a metric.

Troubleshooting

SymptomThings to check
Java container exits on build Ensure network access for Gradle/Git during docker compose build. On Apple Silicon, build uses linux/amd64 — allow extra time.
MQ connection / auth errors Channel MQOTEL.SVRCONN and user app are defined in mq/20-lab-connect.mqsc. Password must match MQ_APP_PASSWORD in .env.
No ibm.mq in Splunk Collector health on :13133; .env.splunk token; wait 1–2 scrape intervals (15s) after startup plus collector batch (5s).
Duplicate metrics Set DISABLE_MQ_OTEL=true and recreate mq (Step 2) so only Java Contrib exports.
Still see ibmmq only Main track exporter still running — complete Step 2 or stop comparing and search both prefixes.

Return to the main lab

To switch back to the default mq_otel track: docker compose --profile java-contrib stop ibm-mq-java-metrics, then DISABLE_MQ_OTEL=false docker compose up -d --force-recreate mq.
